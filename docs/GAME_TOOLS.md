# Hero Kingdom Defense — authoring tools

Open **Tools → Hero Kingdom Defense** in Cocos Creator 2.4.13. Each entry opens a dockable panel. The extension is project-local under `packages`; editor UI and preview code are not included in game builds.

## Editing and saving

Browsing, choosing a model, playing an animation, scrubbing, and inspecting a map do not save game content. Properties edit a shared draft across all panels. **Review** shows the exact fields being changed. **Save changes…** opens a review and requires the final Save button. **Undo**, **Redo**, and **Discard** operate on the shared draft.

A no-change save performs no writes. Numeric edits preserve untouched JSON bytes and number spellings. Existing IDs, optional fields, unknown fields, and data order are retained. If a file with draft edits changes outside these panels, saving stops instead of overwriting it. Untouched files, such as an updated translation catalog, are read again and validated with the draft before saving; their external changes are preserved. A failed save retains the draft and its undo history. Saved files are backed up under `local/game-data-editor/backups/`; multi-file saves have a recovery journal. An interrupted save is shown on reopening and requires an explicit recovery action. Recovery refuses to overwrite subsequent external changes.

After saving, reload an existing game preview to use the new data. The panels do not restart or modify a battle already running. Configuration edits do not change player save files. A Creator import error is reported separately from a completed disk save.

The baseline used during implementation included all existing uncommitted work. No initial overrides or migrated defaults were written to the game's configuration.

## Testing player

Opening **Testing** only reads status. **Start muted test game** opens a managed game window using its own persistent profile for this project. It does not attach to an independently opened Browser or native Simulator save. The profile resumes between sessions and remains muted. Closing the game preserves that test player's progress.

Testing buttons apply immediately to the named managed test player; they are intentionally separate from the configuration draft/Save workflow. Quick buttons grant 99,999 Gold or Gems. The item picker includes the game's currencies and relics. The first relic copy unlocks it; further copies add fragments using the existing game rules. Battle silver requires an active battle and is skipped by a bulk grant outside battle.

Equipment controls set owned levels without changing equipment stats or costs. Talent and stage controls change only test-player progress. Stage progression changes require the home screen. Some appearance/stat changes take effect on reopening their game screen or beginning the next battle, as indicated by the command result.

**Reset test player to the beginning** names the target and requires a typed confirmation. It stops the managed game's writers, captures and verifies a backup under `local/game-data-editor/testing-backups/`, then clears that isolated profile and reloads it. Player progress, items, equipment, rewards and tutorial state restart. Project configuration, map/animation assets, and other players are not reset. Remote-save connections are rejected by the testing command adapter.

The managed game must be ready and development Test Mode must be available. Opening the panel never grants items, starts the game or resets anything. The default keyboard testing controls remain available in its game window.

### Sources and dependencies

- Main data is `assets/KinghtFallConfig/GameJsonCfg.json`. Variants B and D replace complete stage tables; they do not inherit individual stage fields. Common unit/perk/equipment settings remain shared from A. Variant C uses A.
- Stage names and other wording resolve through `assets/resources/localization/catalog.json`. Shared translation usages are identified. Numeric effect edits retain translation placeholders. The historical migration catalog builder is not invoked by these tools.
- Hero base stats come from Equipment. Allies use `AllyCfg`; enemies use `SoldierCfg`. Unit IDs, wave strings and barracks references stay stable, but names, icons, stats, appearances and timings are scoped to the side. Barracks editors modify allied records only. Legacy data without `AllyCfg` retains its original behavior.
- The **Unit collection** filter offers Monster Pack 1, Monster Pack 2, current campaign enemies, and hero/allies. Each imported monster has its own ID, prefab, name, portrait, role and timing, even when its artwork also appears in the campaign. Search accepts names, IDs, roles and imported source identifiers. Wave choices show the role and pack; campaign profile choices identify their original combat controller. New monsters use ordinary `enemy:<ID>:default` override keys; only IDs 90010–90012 are legacy transformation forms. Source-roster registration and campaign assignments are separate operations.
- Imported provenance (`MonsterSource`, `MonsterPack`, `BehaviorTemplate`) stays fixed. The behavior template identifies the existing controller and the meaning of its special parameters; selecting a compatible model variant retains that controller. Names, combat stats, special parameters, role/counters, model transforms/tint/mirroring, attack timing and saved playback speed remain editable independently.
- Campaign appearance variants use `CampaignBaseUnit` to identify the original enemy controller/combat profile and `AppearanceSourceUnit` to identify the imported monster artwork. These provenance fields are read-only. Campaign profiles appear in **Current campaign enemies**; they do not duplicate entries in the two 50-monster source-pack filters. Their stats, timings and special parameters are independent of the source-roster defaults, so swapping a wave's appearance can retain its original combat balance.
- **Unit guide** edits optional `Guide.description` and `Guide.lore` on each allied or enemy record. Both are multiline text. Existing localization tokens edit the selected **Language** (`en` or `zh`) in the shared catalog; literal strings remain literal. Missing guide fields stay absent until typed into, and unknown Guide fields remain intact. Editing wording does not change combat values, role assignments, timings or player progress. The in-game guide derives its displayed role and statistics from current saved unit settings rather than duplicating them in lore. Incoming portraits open the guide only during planning; starting battle closes it and disables portrait input capture. Combat markers remain visual indicators. Use Review and Save to apply guide drafts, just as with other unit fields.
- The six combat roles are **Fighter, Skirmisher, Vanguard, Mystic, Bruiser and Guardian**. Assign a role under **Unit type**. **Countered unit type** applies the existing counter-damage multiplier (currently 1.25x) to every opposing unit in that role; **None** disables the bonus. Roles do not alter AI, movement, weapons or target priority. Types can be added or renamed under **Manage types & pictograms**; referenced types cannot be deleted.
- In **Units**, **Attack animation speed (saved)** accepts 0.1–4× and stays in the shared draft until Save. It applies to attack layers, including the combined cavalry rider and horse, in browser and native Simulation Mode. Temporary **Preview speed** affects only the preview. The gold release marker follows the saved multiplier (for example, a 0.6-second marker plays after 0.5 seconds at 1.2×); its stored value and the authored green reference remain unchanged. **Reset attack speed** removes only this unit's speed override. Movement and the attack interval retain their existing settings.
- Every enemy has its own 128px portrait under `assets/resources/icons/enemy-heads` (campaign) or `assets/resources/icons/monster-roster` (full packs). The unit's selected Battle icon takes precedence over the role's fallback pictogram. Boss forms and imported variants have separate portraits. The source monster artwork is unchanged.
- Spawn waits use the existing `-1` unit marker. Counts, waits, lane order and group order keep their current runtime meaning.
- Stage/wave indices and upgrade branches have runtime dependencies. Invalid new references and cycles block saving. Existing duplicate spawn lanes and an inactive map route placeholder are reported without being automatically repaired.
- In **Buildings**, **Construction choices** edits the ordered `InitialChoices` branch references offered when purchasing an empty plot. Barracks offers its four allied squads immediately; tower plots offer Arrow, Cannon and Sniper. Each selected path keeps its own authored upgrades. Changing the construction list does not change already-built branches or player saves. Remove the list to restore the original direct construction flow.
- Each tower branch retains **Attack damage**, **Attacks per second** and **Attack range** in its existing `Data` values. **Tower attack & targeting** edits optional `Tower` settings: attack type, nearest/highest-current-HP/lowest-current-HP/farthest targeting, projectile speed, Cannon splash radius and edge-damage multiplier, and optional projectile catalog appearance key. Removing the override restores the original arrow implementation; opening a legacy branch does not seed settings.
- **Map artwork & footprint** edits optional `Appearance` sprite artwork from `assets/resources` with displayed width, height, bottom-center offsets, and tower muzzle coordinates. Imported Resources artwork has a picker and a silent static preview. Sprite dimensions include transparent margins. Missing or unsafe resource paths block saving. `ColliderIndex` reuses an original authored collider tag for appended branches; it does not renumber legacy branches. Explicit footprints support new three-level tower paths while legacy map-level limits remain protected.
- **Aiming weapon layer** edits optional `Appearance.weapon` independently of the fixed base. Choose a transparent Resources sprite, width/height, normalized pivot X/Y (measured from the bottom-left), building-local pivot position, and muzzle X/Y relative to that pivot in the reference pose. The game rotates and mirrors only this layer toward its target and fires from the transformed muzzle. Removing the weapon object restores static artwork without changing the base or combat values. The silent composite preview shows the gold pivot and blue muzzle; its aim slider and reference-pose reset never write drafts or player data.
- Asset checks use real resource bundles, imported sprite frames, controller compatibility and available skins/animations. A filename that exists in the wrong bundle is not accepted.
- `AttackPriority` is legacy metadata with no current runtime reader. It is shown read-only. The editor does not invent new targeting rules or new skill implementations.

## Animation and attack preview

The preview renders the actual Spine data in an isolated editor renderer. It does not instantiate gameplay controllers or load the game. There are no audio sources in this renderer. Hero equipment layers and boss forms use the corresponding authored assets.

Use Play/Pause, the timeline, exact seconds, or previous/next frame. The 30/60 FPS grid is a stepping aid; changing it does not quantize saved timings. Preview speed, skin, facing, zoom and temporary hero equipment selections are preview-only.

The **gold marker** is the editable gameplay hit or projectile-release time. **Green markers** are the fixed reference events embedded in the original animation. Use the frame controls and **Use current frame** to move gold to the desired pose; green stays at the authored reference.

For melee/special effects, edit the effect time. For ranged attacks, edit **projectile release**; impact still follows projectile arrival. The target-distance demonstration uses a stationary target and fixed simulation steps, and is labeled accordingly. Actual moving targets change arrival time.

Dragging the timing control or **Use current frame** creates a draft. **Reset to default** removes the custom override and returns gold to the unit's saved default. Save explicitly to apply it. Overrides are scoped to side, unit and boss form, not shared skeleton assets.

On 2026-11-07 the user explicitly approved applying the authored attack-event markers as gameplay defaults for all 17 unit entries. These are stored in `GameTools.timingDefaults`: the hero releases at 0.1667 seconds; all 12 enemy/boss entries and four allied types use 0.5 seconds. `GameTools.timings` holds custom values and takes priority, including an explicit zero. Resetting a custom value restores the saved default. Opening panels never reseeds either table.

The 100 additional source monster rigs contain `idle`, `move`, `attack`, `hit` and `die` animations, but no embedded attack events. Their initial gold defaults are explicit attack-clip midpoint baselines, adjustable in Units. Their preview has no green attack reference; neither importing nor browsing invents events in source animations. The original 17 approved defaults and existing custom timings are retained.

Optional settings are stored under `GameTools` in the existing A configuration. No extra runtime asset is loaded. When neither a saved default nor custom timing exists, attacks retain the original synchronous code path. Delayed effects handle pause, cancellation, death, pooling, form changes and replaced animations. Game speed scales the animation and timing together. Existing projectile/target/damage implementations remain in use.

## Map editing

Maps authors reusable environments. Stages & Waves authors the buildings, hero start, spawn points, routes and wave schedules that use those environments. Opening either panel leaves runtime assets, player progress and Creator's active scene unchanged. Existing maps are adapted in memory; an unchanged Save performs no writes.

**Ground** and **Objects** are separate workspace tabs with a shared icon toolbar, asset library, layer operations and contextual inspector. Ground has foundation, roads and surface grass, plus named overlay layers. Objects places individual scenery with stored random scale ranges. The palette contains maintained source images from eight biomes. Upload PNG/JPEG in either tab; use an image as a brush texture or place it as a whole image. Image position, scale, rotation, flip and opacity remain editable.

Uploads are limited to 40 MB and 16 megapixels per image. Choosing another asset preserves the whole-image placement tool. Locked or hidden layers reject content edits; use their eye and lock controls first. With the canvas focused, V selects, H pans, B paints/places, E erases, P places an image, and D activates Delete Object. Ctrl+D duplicates the entire selection, Ctrl+Z undoes, Ctrl+Shift+Z redoes, and Escape cancels an active drag or brush gesture.

**Soft Eraser** edits a reversible mask. Hardness and opacity appear only for that tool; a 50% stroke removes at most half the alpha per stroke. Image masks stay attached when an image moves or scales. **Delete Object** removes the entire placement; Undo restores it. Ground-layer erasing reveals the layers below without changing the original image file. Whole-image masks can also be restored or cleared.

Rename layers with the pencil control, drag their rows to reorder, or use layer up/down controls. The top of the stack is the front. Ground overlays follow that stack; upright objects continue to sort at their own ground points during play. Move Layer transforms its objects and blockers together. Deleting a layer removes its contents as one undoable edit. Foundation remains below roads, and surface grass remains above roads.


The right dock keeps the contextual inspector above a separate, always visible **Ground layers** or **Object layers** pane. Drag its horizontal divider to change the two panel heights; drag either vertical divider to change the asset browser or right dock width. Double-click a divider to reset it, use its arrow keys for small adjustments, or Escape to cancel a resize. Dock sizes are local editor preferences.

Expand a layer to select its objects by name. Search finds layers and their objects, the focus control frames the corresponding artwork, and **S** temporarily solos one layer while retaining the floor. **Exit Solo** restores the full view. These viewing controls do not change saved visibility. Map01 keeps its original named layers, including `dt1_4`; Add Layer immediately displays and selects the new layer.

With Select active, corner handles scale the selection and the round handle rotates it. A single object uses its ground pivot; multiple objects transform together. Shift snaps scaling to tenths and rotation to 15 degrees. Each completed gesture is one undo step; Escape cancels it. Paint and eraser tools show a footprint with the selected size and hardness. Hold Shift when starting a stroke for a straight segment, and use **Texture tiling** to adjust the painted texture size independently of the brush.

Star assets to keep a local **Favorites** collection. Under **Saved groups**, capture selected scenery or an entire object layer, optionally including its blockers. **Save library** explicitly stores reusable groups and their required source images in `authoring/worlds/library/groups.json`. Library undo/redo and discard are separate from map edits. Choose a group to preview and stamp it onto any map as a new movable layer, with editable scale and rotation. Copies retain their original sources, masks and blockers even if the library entry is later removed. Painted ground layers are edited in Ground rather than captured as scenery groups.

**Map cost…** shows visible placement counts, generated atlas pages, existing scenery textures and estimated uncompressed texture memory. The same estimate appears before shared-map Save. It deduplicates reused textures and uses the actual baker's atlas layout; units, buildings, UI, platform compression and driver overhead are outside this estimate.

The canvas reuses bounded ground and scenery previews while panning; it redraws only when needed and stops rendering when idle. Appended strokes update cached layers, and undo stores changed array sections rather than copying the complete paint history. Preview rasters have a maximum edge of 2048 pixels; saved maps bake at their authored resolution. Legacy foundation images remain editable and retain their source references across saves and editor restarts.

The blocker brush paints a 20-unit navigation grid and supports erased openings. Original collider polygons remain exact until explicitly converted with **Convert existing blockers to brush grid**. Visual image erasing does not silently change collision. Stage 7 has an explicit **Recover 95 original Stage 7 props** action that restores its maintained source placements and clean cliff chunks to a draft.

**Duplicate** in Maps creates a separate map ID and draft. Saving it leaves the source map unchanged. Shared-map Save lists affected stages and updates their environment while retaining each stage's layout. Maintained definitions and original image sources live under `authoring/worlds/`; Save produces atlased sprites, ground textures no larger than 2048×2048, thumbnails and stage prefabs under `assets/KinghtFallIconMap/Generated/`.

Stages & Waves has Stage, Buildings, Spawns, Paths and Waves tabs. Buildings use complete existing assemblies and main-hall availability levels 1–3. Silver, weapon and horse offers are special placements. Spawn IDs are stable and can be added or removed. Convert an individual legacy wave explicitly to edit overlapping unit groups by start time, count and interval; unconverted waves retain their legacy queues. Routes use draggable nodes, weighted forks, building conditions, fallback branches and goals. Combat target selection still uses the existing AI. The route preview distinguishes the authored line from calculated navigation and treats a closed attackable gate as a valid frontier.

All edits remain shared drafts until explicit Save. Revision checks protect concurrent changes; saves keep external backups and rollback journals. Refresh retains dirty drafts and reloads clean data. **Preview draft** opens a muted game window with an ephemeral player and in-memory configuration; closing it leaves the normal player and active editor scene untouched. This authoring preview bypasses onboarding through temporary guide queries and waits for startup navigation to settle before showing the battlefield. Concept art, diagnostic images, recovery copies and test exports stay outside the repository.

## Verification

Run `node packages/game-data-editor/test/run.js` from the project root. The tests exercise source-preserving saves, conflicts/rollback/recovery, semantic and resource validation, map edits and route planning, scoped timing, original attack traces, and actual Spine poses. Save tests use temporary project copies.

Full-roster script checks resolve every imported monster's source rig, skin, five animations, portrait, compatible controller, role and wave choice. Creator's Spine parser verifies texture pages, geometry, changing attack poses and deterministic backward seeks for every reachable unit. Pack filtering, searching and browsing all new records are checked for zero drafts and zero file writes; eventless rigs are checked for no invented green markers. Guide checks cover locale edits, optional fields, queued edits, unknown-field preservation, exact backup and no-change Save. These checks do not launch Creator or a game session.

Live Creator checks cover all dockable panels, shared draft editing/undo, and silent visual previews. A muted isolated browser loaded all 17 saved animation defaults, and controlled actors exercised their hit/release dispatch through the compiled runtime. The live Units panel was checked for resetting gold to the saved default and moving gold independently of green; the user's drafts and history were restored afterward. Native verification runs the helper in real Windows JSB with injected actors; it is not a complete interactive native combat certification.

Other project work may modify UI assets concurrently. The tools never restore unrelated files to the captured baseline. Current game balance, map and animation files are not rewritten as part of installation.
