# Game verification

Run `npm test` from the project root using Node 22 or newer. No npm install or third-party packages are required. The command runs every regression test, localization runtime and source checks, artwork availability, all authored navigation routes, and serialized asset/import checks. It exits nonzero if any group fails. Reports are written to ignored `local/audit/` directories, created automatically. GitHub Actions runs the same command on pushes and pull requests.

The navigation runtime suite uses the installed Cocos implementation when `COCOS_ENGINE_DIR` points to its engine folder. Without Creator it uses its portable geometry mock. The real Spine animation integration requires Creator 2.4.13 (`COCOS_ENGINE_ROOT` points to its engine folder); the test explicitly reports a skip when Creator is absent, including in default CI. A configured but invalid engine path fails. Run on a Creator-equipped machine before release to include this integration check. The serialized asset audit uses a checked-in UUID inventory from Creator 2.4.13 default assets; regenerate this inventory when upgrading the engine.

Current artwork coverage and localization validity do not prove preservation against historical copies. Optional historical checks require the original baseline: `node tools/localization/audit-art-coverage.cjs --baseline path/to/inventory.json` checks image hashes; `node tools/localization/audit-project.cjs --baseline path/to/original/assets` compares gameplay values against original configuration files. A supplied incomplete/missing baseline fails. No ignored machine-specific backup is needed for the default checks.

For runtime validation, open the project in Cocos Creator 2.4.13 and preview at 375 × 667 and a wider phone viewport. Check home, sign-in, Battle Pass and playtime claims, English/Chinese switching, battle entry, movement, pause/resume, victory, defeat and revive. Use isolated test saves for failure injection. Keep F8 development rewards disabled when checking normal ads; release builds must never enable them.

The navigation regression suites exercise shipped enemy/soldier classes against real map and prefab geometry. They cover Map01 gate levels 1–3, rally/follow in both directions, enemy exclusion, persistent orders after revival, combat along the route, retaliation against melee/ranged attackers, slow pursuit, and recovery when geometry or an overlapping unit's position changes. `tools/navigation/stress.test.cjs` uses 100 units and asserts at most eight path searches per game frame, one geometry build for an unchanged scene, safe movement after removing a gate, and fair scheduling while the destination moves. Its elapsed times are diagnostic Node harness measurements, not browser/device FPS.

For reproducible live gate checks, build a fresh **debug** web-mobile export. Set `LIVE_GATE_EXPORT` to its `web-mobile` directory, then run `node tools/navigation/install-live-panel.cjs --sync-export` and `node tools/navigation/serve-live.cjs` with that environment variable. Without it the tools use `local/live-gates/export/web-mobile`. Open `http://127.0.0.1:8787/?live-gates=1`. The installer modifies only the disposable export: a mute bootstrap runs before Main imports, locks the game's music/effect controls off in isolated memory, and guards engine/source volume controls. The source-Main installation path is disabled; `--remove` remains available for restoring an older source hook. Never ship the diagnostic export.

The panel uses the actual game, barracks, physics, animation and combat code, with isolated in-memory saves. Its environment report verifies the real game audio controls are muted. It measures wall-clock frame intervals separately from game-update, physics and navigation costs. Save the results JSON before reloading and close the temporary browser/server afterwards. The optional `sync-live-source.cjs` refreshes named gameplay modules in this disposable debug export and records their source hashes; it is not a release build command.

Do not assume an already-running editor preview contains current source. Check compilation or build a fresh export, particularly when the editor has automatic compilation disabled. For large crowds, inspect actual crossing/respawn outcomes and physics displacement as well as route validity: a clear static path alone does not prove that solid units can pass one another.

Release validation additionally needs an exported build on the chosen host and real target devices. Verify the host ad SDK, completion/cancellation/offline/timeout behavior, suspend across midnight, slow/failed asset requests, storage failure recovery, full campaign boundaries, and sustained combat performance. Automated mocks do not certify host ads, device performance, or all 200 campaign waves.
