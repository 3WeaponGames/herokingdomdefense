# Game verification

The [PCMain merge verification](audits/2026-11-07/pcmain-merge.md) records the latest integrated branch checks. The earlier full backend audit below is a frozen pre-merge checkpoint.

The [completed 2026-11-07 backend audit](audits/2026-11-07/backend-audit.md) records ten whole inspection passes, the final 695-entry installed-engine run, portable compatibility results, native reward failure controls, and silent actual-game gate/rally/follow/respawn verification. Its [manual visual kit](audits/2026-11-07/visual-review/index.html) keeps visual reports separate from backend repairs. Exact current evidence and limitations are in the audit report; earlier checkpoint counts below and in older reports are historical.

Run `npm test` from the project root using Node 22 or newer. No npm install or third-party packages are required. The command runs every regression test, localization runtime and source checks, artwork availability, all authored navigation routes, and serialized asset/import checks. It exits nonzero if any group fails. Reports are written to ignored `local/audit/` directories, created automatically. GitHub Actions runs the same command on pushes and pull requests.

The optional Python bridge suite uses Python 3.12 and only the `websockets` dependency; it does not require FastMCP or start a server. In an isolated Python environment, run `python -m pip install "websockets==17.4"`, then `python -m unittest discover -s packages/cocos-mcp-2x/server/tests -p 'test_*.py' -v` from the project root. The separate GitHub Actions bridge job runs this command with both `websockets==12.0` and `websockets==17.4` to verify the installed legacy and modern handshake implementations, connection/request lifecycle, nonblocking owned-thread shutdown and typed node-property null values. Every transport is inert: no editor, game, socket listener, or audio is started.

The navigation runtime suite uses the installed Cocos implementation when `COCOS_ENGINE_DIR` points to its engine folder. Without Creator it uses its portable geometry mock. The real Spine animation integration requires Creator 2.4.13 (`COCOS_ENGINE_ROOT` points to its engine folder); the test explicitly reports a skip when Creator is absent, including in default CI. A configured but invalid engine path fails. Run on a Creator-equipped machine before release to include this integration check. The serialized asset audit uses a checked-in UUID inventory from Creator 2.4.13 default assets; regenerate this inventory when upgrading the engine.

Current artwork coverage and localization validity do not prove preservation against historical copies. Optional historical checks require the original baseline: `node tools/localization/audit-art-coverage.cjs --baseline path/to/inventory.json` checks image hashes; `node tools/localization/audit-project.cjs --baseline path/to/original/assets` compares gameplay values against original configuration files. A supplied incomplete/missing baseline fails. No ignored machine-specific backup is needed for the default checks.

For runtime validation, open the project in Cocos Creator 2.4.13 and preview at 375 × 667 and a wider phone viewport. Check home, sign-in, Battle Pass and playtime claims, English/Chinese switching, battle entry, movement, pause/resume, victory, defeat and revive. Use isolated test saves for failure injection. Keep F8 development rewards disabled when checking normal ads; release builds must never enable them.

Check Browser and native Simulator separately. Creator 2.4.13's native Spine bindings do not expose the browser runtime's `getBounds` or mutable pose objects. `KinghtFallDepthView` uses native animated bounds and GPU captures of live visual nodes on Simulator; Browser retains its cached pose/vertex silhouette pass. Native actor captures are shared across overlapping object stencils, with the same blue ally/red enemy tint and opacity. Check the hero behind a building and gate, scenery clipping, moving in front, actor removal, and stage teardown. Verify both Continue with a copied existing save and a fresh stage; resetting progress is not a remedy for renderer mismatches. Restart Simulator after importing new scripts/effects so Creator regenerates its resource manifest. Keep previews muted before boot, isolate storage, and close temporary verification sessions.

After clearing stage 1, follow the Equipment tutorial from the lobby tab through upgrading and the next tutorial steps. Frames must keep advancing and tabs must remain responsive without exceptions. Creator destroys child nodes before a component's `onDestroy`: lobby teardown must detach input/event subscriptions without traversing released chest-popup children. `chest-preview-regressions.test.cjs` covers this ordering.

Check Battle Perks after a Simulator battle transition as well as on first open. Its native sprites use original textures to avoid stale dynamic-atlas regions; packed frames get modal-owned wrappers so other live UI bindings remain untouched. Verify the ribbon, three card backgrounds, both action buttons and both ad icons, then close/reopen the popup. The subtitle uses the regular compact font while the title and actions retain Lilita One.

The navigation regression suites exercise shipped enemy/soldier classes against real map and prefab geometry. They cover Map01 gate levels 1–3, rally/follow in both directions, enemy exclusion, persistent orders after revival, combat along the route, retaliation against melee/ranged attackers, slow pursuit, and recovery when geometry or an overlapping unit's position changes. `tools/navigation/stress.test.cjs` uses 100 units and asserts at most eight path searches per game frame, one geometry build for an unchanged scene, safe movement after removing a gate, and fair scheduling while the destination moves. Its elapsed times are diagnostic Node harness measurements, not browser/device FPS.

`tools/navigation/friendly-orders.test.cjs` also checks formation destinations against the gate approach reserved by crowd settling. It includes the two contact positions recorded in the live 60-unit inward crossing, rejects their old destinations, and verifies safe routes to replacement destinations. The headless harness uses shipped controllers and authored geometry; it does not simulate solid-unit Box2D contacts or certify that a rendered crowd is smooth.

`tools/navigation/crowd-integration.test.cjs` combines 60 allies with 100 enemy navigation requests on Map01, deliberately placing enemy requests first. It checks rally/follow in both directions, shared search limits, an intact gate opened for allies, and recovery after destruction. A separate case uses normal barracks timers for 20 revivals, the saved attack delays, retaliation damage hooks, and return to the retained rally. Scene/effect adapters and explicit animation completion keep these tests headless; combat acquisition is isolated from the 160-request routing case.

`tools/testing/spine-render-state.test.cjs` runs Creator's actual RenderFlow and Spine/Sprite assemblers headlessly. It reproduces the empty-Spine transform-counter underflow, static HP backgrounds trailing moving units, and collapsed first-open popup backgrounds, then verifies the project guard restores balanced counters and correct geometry. It covers nested renderers, runtime skeleton changes, compatibility exclusions and idempotency. It does not launch a preview or use a graphics device.

`tools/testing/joystick-lifecycle.test.cjs` checks touch ownership and end/cancel/disable resets. `tools/testing/audio-lifecycle.test.cjs` uses silent audio adapters and the shipped manager/hero callbacks to check pending-load races, pause/stop/preferences, bounded effect bursts, failed replacements, app-resume loop recovery and death/revival volume restoration. These tests never enable audio and do not certify native audio output or diagnose every device interruption.

For reproducible live gate checks, build a fresh **debug** web-mobile export. Set `LIVE_GATE_EXPORT` to its `web-mobile` directory, then run `node tools/navigation/install-live-panel.cjs --sync-export` and `node tools/navigation/serve-live.cjs` with that environment variable. Without it the tools use `local/live-gates/export/web-mobile`. Open `http://127.0.0.1:8787/?live-gates=1`. The installer modifies only the disposable export: a mute bootstrap runs before Main imports, locks the game's music/effect controls off in isolated memory, and guards engine/source volume controls. The source-Main installation path is disabled; `--remove` remains available for restoring an older source hook. Never ship the diagnostic export.

The panel uses the actual game, barracks, physics, animation and combat code, with isolated in-memory saves. Its environment report verifies the real game audio controls are muted. It measures wall-clock frame intervals separately from game-update, physics and navigation costs. Save the results JSON before reloading and close the temporary browser/server afterwards. The optional `sync-live-source.cjs` refreshes named gameplay modules in this disposable debug export and records their source hashes; it is not a release build command.

Do not assume an already-running editor preview contains current source. Check compilation or build a fresh export, particularly when the editor has automatic compilation disabled. For large crowds, inspect actual crossing/respawn outcomes and physics displacement as well as route validity: a clear static path alone does not prove that solid units can pass one another.

Release validation additionally needs an exported build on the chosen host and real target devices. Verify the host ad SDK, completion/cancellation/offline/timeout behavior, suspend across midnight, slow/failed asset requests, storage failure recovery, full campaign boundaries, and sustained combat performance. Automated mocks do not certify host ads, device performance, or all 200 campaign waves.

`tools/testing/lobby-tabs.test.cjs` checks reuse of visited lobby pages, listener suspension for hidden pages, current equipment limits on return, locked tabs and destroyed-page recovery. `tools/localization/ribbon-layout.test.cjs` covers folded ribbon faces, sibling stage captions and Battle Pass banners. `tools/testing/energy-info.test.cjs` verifies the read-only energy countdown, full/overflow states and Chinese text. The energy display uses the existing cap and recovery interval; these UI changes do not introduce stage-based energy limits. Live browser tab timings are preview measurements, not native-device performance guarantees.

The mission drawer tests cover left-edge alignment, viewport resizing, rapid toggles, reward-dot states, and keeping arrow taps separate from reward claiming.
